# USBPcap-ARM64 v0.1.0 — source-first release (draft)

**Status: DRAFT — not published.** No git tag, GitHub release, binary attachment, or package has been created. This note is prepared for maintainer review; publication is a separate, explicitly authorized step.

This is a **source-first** release: source code, build system, tests, and documentation only. It intentionally contains **no installable or signed driver binaries** and no supported driver-deployment path.

## What a v0.1.0 release would include

- The full ARM64 port source tree on top of upstream `desowin/usbpcap` @ `477b6edcbd7e99a47f77afc0c4168a9ebee603bb` (2025-01-25), with complete upstream history retained.
- The native ARM64 build system (`build/arm64/`) for VS 2022 v143 with pinned SDK/WDK NuGet packages `10.0.26100.3323`.
- Static build-contract tests (52) and source-contract hardening tests (16) — Python stdlib only, no compiler required.
- Documentation: `README.md`, `build/arm64/README.md`, and this release note.
- License texts: GPL-2.0 (driver), BSD-2-Clause (CLI), and retained upstream notices.

## What it explicitly does NOT include

- **No signed or installable driver binaries** — no `.sys`, no `.cat`, no MSI/NSIS installer, no ZIP of built binaries attached to the release.
- No production signing, attestation, or Microsoft-signed packages.
- No instructions to install, load, or deploy the driver as a supported end-user path. The legacy installation/signing notes in the README remain upstream-only context.
- No hardware validation claims — nothing here is evidence of driver load, USB capture, or device compatibility on real machines.

## Build status and evidence scope (honest)

- **Static + hardening contract tests** — run in CI (strict stage) and reproducible locally via `python build/arm64/build.py --static-only` and `python build/arm64/test_hardening.py`. These are source-contract checks; they do not compile or qualify a kernel driver.
- **Compile/link** — enforced as a strict CI gate on the hosted `windows-11-arm` runner (missing toolchain and build failures fail the job). **No successful compile is claimed by this draft.** Earlier CI runs treated the toolchain probe and build as informational (`continue-on-error`), so a green badge from that period is not compile evidence; compile/link evidence is whatever the latest strict run records.
- **Hardware** — never tested by this repository. There is no driver-load, Driver Verifier, HLK, Secure Boot/HVCI, or capture evidence here, and none is implied.
- **Offline bundle** — when a full build completes, the build tooling produces an explicitly unsigned, offline research bundle labeled `DO NOT INSTALL OR LOAD`. It is not an end-user artifact and is not part of this release.

## Building from source

Dependencies (VS 2022 Build Tools with the v143 ARM64 target compiler, Python 3.9+, and the pinned NuGet packages) are restored/installed separately; the build script never downloads, installs, or deploys anything. See `build/arm64/README.md` for prerequisites, commands, and the offline validation stages:

```sh
python build/arm64/build.py --static-only           # static contracts only
python build/arm64/build.py --configuration Release # full ARM64 build + validation
```
